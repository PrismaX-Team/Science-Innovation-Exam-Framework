# Matrix scoring

此模块作为独立计算库保留，不参与当前 CPU 实验主流程。文中的哈希字段属于其独立分析输入合同，不是实验启动要求。旧运行数据库、Arena CLI 和工件仓库已从实验框架移除。任务包里 `metric` / `transform` / `baseline` 锚点的字段合同见[任务包合同](../contributor/build-sie-task-package/task-contract.md)。

Matrix 现在把三个不同问题分成三层。混用三层会让一个看起来精确的总分表达错误含义。

1. **原始分**：任务自己的固定 Verifier（评分程序）产生的科学测量，是权威结果。
2. **展示分**：把单题原始分换算成便于阅读的 0/1000 参考坐标，只用于解释单题进展。
3. **Arena 对比分**：把同题、同条件下的胜负用 Bradley–Terry 模型汇总。Bradley–Terry 是一种由两两胜负估计相对强弱的统计模型，用于总榜。

展示分不进入 Arena 拟合；Arena 不直接比较不同任务的原始数值。因而“准确率 0.8”不会和“误差 12.4”做数值平均。

## 第一层：原始分

每个任务在 Agent 开始前固定指标名称、计算方法和方向：`maximize` 表示越大越好，`minimize` 表示越小越好。原始分回答“这个提交在该任务上达到什么科学结果”，任何换算都不能替代它。

任务还要固定 `tie_tolerance`，即多小的差异视为并列。这个容差来自指标的数值噪声或科学分辨率，不能看完参赛结果后调整。

## 第二层：冻结展示分

### 锚点

每个 benchmark release（一次不可变的榜单发布版本）先完成一次校准批次，再冻结两个方向一致的锚点：

- 校准批次中最差的合格结果映射为 `0`；
- 有可复现公开 baseline（固定参考方法）的任务，把该 baseline 映射为 `1000`；
- 没有这种 baseline 的任务，把校准批次中最好的合格结果映射为 `1000`，此后把它视为该任务的参考结果。

这里的“最好/最差”是对每个配置的重复实验先按冻结的 `mean` 或 `median` 汇总后，再按任务方向判断，不是挑一次幸运运行。校准候选、种子、资源、模型设置、原始结果和选择规则必须放进带 SHA-256 的不可变校准工件。基础设施或评分器故障不参加锚点选择；Agent 自身产生的无效提交也不能成为数值锚点。

推荐用选择分区确定最好和最差的配置，再用互不重叠的确认分区测量锚点原始值，降低“从一批随机波动中挑最高者”造成的虚高。若公开 baseline 不严格优于校准最差结果，它不能形成单调的 0/1000 坐标；该 release 必须改用校准最好结果作 1000，并把公开 baseline 作为普通结果展示。

### 公式

令 `q(x)=x`（越大越好）或 `q(x)=-x`（越小越好），则：

```text
display_score = 1000 * (q(raw) - q(worst)) / (q(reference) - q(worst))
```

不截断结果：未来优于参考结果可以超过 1000，差于校准最差结果可以低于 0。无效提交没有展示分，而是单独显示无效状态；不能用人为负分冒充原始科学结果。锚点或校准工件改变时必须建立新 release，已经发布的展示分不会因后来增加 Agent 而变化。

展示分只回答“相对本题校准区间处于哪里”。不同任务的 1000 所代表的绝对难度不同，因此不得平均展示分来声称总体能力。

### 已实现合同

`display_scale.schema.json` 固定 release、任务 payload、指标、校准证据、锚点来源、精度和舍入；`display_score_result.schema.json` 固定结果。纯计算入口是：

```python
from science_innovation_exam.matrix import DisplayScaleEngine

result = DisplayScaleEngine().score(display_scale, verifier_result)
```

所有冻结常量使用十进制字符串；计算使用 `Decimal`，避免二进制浮点数改变边界。`calibration_best` 与 `reproducible_baseline` 是两种明确来源，不能只写一个含义不明的“baseline”。

## 第三层：跨任务 Arena

### 从原始分生成同题胜负

Arena 只在相同任务、相同重复实验标识下比较两个参赛者：

- 方向调整后的差值大于 `tie_tolerance`：胜者得 `1`，败者得 `0`；
- 差值在容差内：双方各得 `0.5`；
- Agent 自身的无效提交对有效结果记负；双方都无效记平，并另外公布无效率；
- 基础设施或评分器故障没有比赛结果。正式快照要求重跑补齐，不能把系统故障算成 Agent 失败。

每个任务都有参考结果。已有可信 baseline 时使用它；否则使用该任务校准批次最好结果的冻结工件。所有任务的这些不同工件合起来称为 **reference portfolio（参考组合）**。它是一个统计坐标，不是假装由同一个真实 Agent 完成了全部任务。

### 公平权重

Bradley–Terry 能消除指标单位和数值范围差异，但不会自动消除题目分布偏差。V2 因此固定分层等权：

```text
领域等权
└── 每领域内独立题族等权
    └── 每题族内任务等权
        └── 每任务内重复实验等权
            └── 每次重复内参赛者对等权
```

“题族”指共享主要数据、科学目标或构造来源的一组相关任务；把同一底层问题改写成十题仍只占该题族的固定份额。每次重复内再除以参赛者对数，所以增加 Agent、两两组合或重复次数不会增加某个任务的总权重。领域、题族归属必须在结果出现前冻结。

### Bradley–Terry 输出

对参赛者 `i` 和 `j`，模型为：

```text
P(i beats j) = 1 / (1 + exp(-(theta_i - theta_j)))
```

`theta` 是 `bt_strength`，只有差值有意义；整体同时加一个常数不会改变胜率。实现把参考组合固定为 `theta=0`，并同时发布更直观的：

```text
reference_win_probability_percent = 100 * sigmoid(theta)
```

因此参考组合恒为 50%；正 `theta` 表示预期强于参考，负值表示弱于参考。榜单发布排名、`bt_strength`、相对参考胜率、置信区间、所有两两预测与实际结果、无效率和不可用率。V2 使用按每个参赛者实际比较权重缩放的显式 L2 正则；“正则”是在样本很少或全胜时防止强度跑到无穷大的轻微约束，其强度属于冻结模型配置。

### 不确定性与代表性

同一任务和同一次重复实验产生的许多两两记录彼此相关，不能把它们伪装成大量独立样本。置信区间按冻结的领域、题族、任务或“任务＋重复实验”整体重采样，再完整重拟合；绝不逐条重采样参赛者对。

一个标量总榜隐含“所有领域大致共享同一条强弱轴”。专门模型可能在不同领域形成循环优势，使这一假设失败。因此每个快照同时发布：

- 各领域单独的 Bradley–Terry 排名；
- 模型预测概率与实际两两得分的加权误差；
- 每次去掉一个领域后排名的最大变化；
- 数据完整性、领域数、独立题族数和任务数检查。

这些门槛全部在 `representativeness_gate` 中预先配置。任一检查失败，仍可查看探索性拟合，但结果标记为 `representativeness=failed`，不得称为有代表性的综合能力分。

Arena 是相对模型：加入新 Agent 可能改变联合拟合。每次公开结果必须保存不可变 `snapshot_id`、完整输入和输入 SHA-256；需要永不变化的数字时只能另报“直接对参考组合的固定胜率”，不能把它冒充全池 Bradley–Terry 排名。

### 已实现合同

`cross_task_arena_input.schema.json` 固定实验政策 SHA-256、参赛配置 SHA-256、参考组合、任务层级、完整结果网格、每条结果工件 SHA-256、权重、拟合、重采样和代表性门；每项任务还绑定其参考来源及工件 SHA-256。`cross_task_arena_result.schema.json` 固定公开输出。纯计算入口是：

```python
from science_innovation_exam.matrix import BradleyTerryArenaEngine

result = BradleyTerryArenaEngine().analyze(frozen_arena_input)
```

实现按参赛者 ID、任务和重复标识规范排序，因此同一语义输入不会因 JSON 数组顺序不同而改变快照哈希或结果。比较图若不连通、参考组合缺结果、网格缺行、正式快照仍有系统故障或拟合不收敛，均停止而不是发布部分排名。

## V1 兼容边界

原有 `MatrixEngine`、`meta.json.metric.transform`、内置线性/对数/残差/幂/分段变换和任务自带 `verifier/matrix/transform.py` 暂时保留，保证旧任务与测试不被破坏。它们产生的固定锚点分现在定义为 **V1 展示分**，不再被解释为天然可平均的跨任务能力分，也不作为 V2 Arena 输入。

原有 `ArenaAnalysisService` 仍是单任务、冻结 cohort（参赛运行集合）的均值/中位数分析，不是这里的跨任务 Bradley–Terry Arena。两个接口在迁移完成前并存，调用方必须显式选择。
